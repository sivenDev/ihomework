# 现状评估中心与评估报告 Plan

**Goal:** 让家长用 3～4 次、每次不超过 20 分钟的评估，摸清孩子的识字、书写、词汇、朗读和写作现状（基础弱的找出缺口，基础好的测出上限），并能每 4 周复评对比。

**Scope:**
- **课内认读抽测**：从已学识字表按册随机抽字（每册 30～40 个，数量可调），一屏一个大字；家长点“对 / 错”；可以中途暂停，下次接着做。
- **拓展认读抽测**：课内认读正确率 ≥ 90% 时自动加测。从未学的后续课本字和拓展字库按常用度分层（例如每 500 字一层）各抽 10 个；某一层正确率低于 30% 时停止往下测。按各层正确率 × 该层字数之和估算课外识字量。
- **听写**：系统朗读字词，孩子在纸上写，家长逐个标记“写不出 / 写错 / 正确”。
- **组词与词语理解**：出字让孩子口头组词，出词让孩子说意思或造句，家长判定。
- **朗读计时**：家长粘贴文本，计时并记录卡顿次数，计算每分钟字数。
- **看图写作评分**：家长选择图片（存入本地），按 5 项评分表（每项 1～3 分）打分，可附作文照片；再对照写作等级阶梯（PRD 4.6）选出孩子当前达到的等级，作为计划 07 的起始等级。
- **评估报告**：课内识字量（各册正确率 × 该册已学字数之和）、课外识字量、书写正确率、写作等级、待攻克清单、“优先补识字 / 优先补写作”建议、**建议学习路线**（补漏 / 同步 / 拓展）和**建议练习级别**（轻松 / 标准 / 加强）；保存历史，可以与上次对比。
- 待攻克清单保存为“补漏来源”，供计划 06 的补漏路线按天取字。
- 认读和听写中出错的字交给错字 Boss（通过计划 04 提供的接口；若计划 04 尚未完成，先写入待处理队列，计划 04 接入时导入）。

**Non-Goals:**
- 不做语音识别自动判定，所有判定由家长完成。
- 不做跨家庭常模比较；只和课本要求及自己的历史比较。

**Architecture:**
- 报告计算（识字量估算、建议规则）是纯函数，放在 `src/features/assessment/logic/`，与界面分离。
- 建议规则：认读正确率 < 75% → 优先补识字；认读 ≥ 90% 且写作总分 ≤ 9/15 → 优先补写作；其他情况 → 识字与写作并行。阈值集中定义为常量。
- 路线建议规则（PRD 4.5.2）：课内认读 ≥ 90% 且书写 ≥ 85% → 拓展（首次评估达标即可进入，个别错字仍进入错字 Boss）；否则待攻克清单不为空 → 补漏；其他 → 同步。
- 级别建议规则（PRD 4.5.3）：课内认读 < 75% → 加强；其他 → 标准。报告中注明“基础好的孩子想多学，可以选加强”。只作建议，由家长在计划 06 的设置中决定。
- 图片和照片以 Blob 存入 IndexedDB，导出时编码进 JSON。

**Exit Criteria:**
- 五项评估都能从家长模式开始并完成，中断后可继续。
- 报告数值与单元测试中的手算样例一致（含课外识字量的分层估算和提前停止）；补强建议、路线建议和级别建议的各个分支（含 75%、90%、85% 边界值）都有测试。
- 历史中至少两次评估时，报告页显示前后对比。
- `npm run verify` 与 `npm run test:e2e` 通过。

## Task 1: 评估计算逻辑

**Outcome:** 课内外识字量估算、正确率、待攻克清单和各项建议规则可以独立测试。

**Files:**
- Create: `src/features/assessment/logic/report.ts`, `src/features/assessment/logic/sampling.ts`
- Test: `src/features/assessment/logic/report.test.ts`, `src/features/assessment/logic/sampling.test.ts`

**Verification:**
- `npx vitest run src/features/assessment`

- [x] 估算、抽样（课内只抽已学范围、拓展分层抽样、不重复）、补强建议、路线建议和级别建议测试通过

## Task 2: 五项评估流程与报告页面

**Outcome:** 家长可以完成全部评估（拓展认读按条件出现），查看报告和历史对比。

**Files:**
- Create: `src/features/assessment/` 下各评估页面与报告页
- Modify: `src/db/schema.ts`（评估记录、图片）
- Test: `e2e/assessment.spec.ts`

**Verification:**
- `npm run verify`
- `npm run test:e2e`

- [x] 一次完整评估生成报告并保存；第二次评估后显示对比

## Evidence（2026-10-19）
- 规则调整（与 PRD 4.5.2 对齐）：路线建议先判断“拓展”（认读 ≥ 90% 且书写 ≥ 85%），再判断“补漏”，否则基础好的孩子在首次评估中几乎不可能进入拓展路线。
- 补充的边界处理：进度靠前、还没有写字表的字时，听写（以及组词）没有题目，直接算完成；生成报告至少需要完成课内认读和听写，拓展认读开放后也需要完成，其余部分可选。
- `npm run verify`：Vitest 65 个测试通过。新增评估相关测试 26 个，覆盖：抽样（只抽已学、每册上限、不重复）、拓展分层（每 500 字一层、低于 30% 停止、撤销等待）、听写和组词抽题、报告手算样例（课内与课外识字量、听写、组词、朗读、写作）、补强 / 路线 / 级别建议的 75%、85%、90% 边界、各部分状态与可生成报告条件、错字写入待处理队列（不重复、合并来源）。生产构建通过。
- `npm run test:e2e`：17 个测试通过（新增 4 个：两次完整评估——第一次 80% 生成补漏建议，第二次全对开放拓展认读、报告显示“比上次多 3 字”和拓展路线；认读暂停、刷新后继续、撤销；组词、朗读计时（模拟时钟）、看图写作（上传图片、评分、等级）；未设置进度时引导设置）。`assessment.spec.ts` 重复运行 3 次稳定。
- 发现并修复：朗读计时的开始时间原来在保存数据之后才记录，现在按点击时刻计时。
- 待后续：认读大字目前使用系统字体（安卓上为黑体），楷体字形可在计划 04 引入田字格和楷体字体时统一处理。
